## ✨ 它能做什么

群友说一句话，Bot 用它回你，**声音是动森村民那种叽里咕噜的腔调**。

不是 TTS，不是变声器——是从 407 个真人录制的普通话音节里挑出来拼的，
和《动物森友会》本体用的是同一套方法。

```
用户：今天好热啊
Bot：  🔊（动森腔）「就是啊，热得我都想跳进河里了」
```

## 🎛 全部参数，滑块搞定

装好后打开 WebUI → 插件 → 动森语音 → 配置，九个参数全是可视化控件：

| 参数 | 控件 | 默认 |
|---|---|---|
| 启用自动语音回复 | 开关 | 关 |
| **自动语音触发概率** | 滑块 1-100 | **100** |
| 音高 | 滑块 300-700 | 400 |
| 语速 | 滑块 5-25 | 13 |
| 最大字数 | 滑块 10-300 | 150 |
| 最小字数 | 滑块 1-20 | 2 |
| 允许会话内覆盖 | 开关 | 开 |
| 同时发送文字 | 开关 | 关 |
| 临时音频保留 | 滑块 1-120 分 | 10 |

### 概率语音

把概率设成 **30**，就是十条回复里大约三条发语音、七条保持文字。

既有点缀效果，又不会让不方便听语音的人难受。

## 🎵 音色参数怎么调

### 音高

| 数值 | 听感 |
|---|---|
| 364 | 音库原音，最自然 |
| **400** | 动森实际音域（默认） |
| 480 | 偏尖，更像小动物 |
| 560+ | 花栗鼠 |

音高越高，语音越短——这是物理规律，不是 bug。

### 语速

| 数值 | 听感 |
|---|---|
| 10 | 慢，每个字都听得清 |
| **13** | 接近原版（默认） |
| 18 | 叽里咕噜 |
| 22+ | 很快，可能糊 |

## 🔬 它是怎么发声的

```
文本
 └→ 汉字查表得 (音节, 声调)
     └→ 从 407 个音节单元里挑对应音节
         └→ 按声调算出播放速率曲线
             └→ 变速播放（音高随之改变）
                 └→ 按标点插入停顿
```

核心洞察：**音高只靠播放速率改变**，所以越高越短。
声调幅度被压到 0.35 倍——这就是动森语听着"平"却不像念经的原因。

音色 EQ 按《动物森友会》中文对话实测：2/3 次谐波压到基频下 11-13 / 16-20 dB，4 kHz 以上能量低于 1.5%。

## 🐛 已知问题

诚实列出，都是实测确认的。**装之前先看一眼，能接受再装。**

### 1. 多音字读错（影响最大）

字表只存每个字的**最常见读音**，不看上下文。实测：

| 词 | 正确 | 实际合成 |
|---|---|---|
| 银行 | yín **háng** | yín **xíng** ✗ |
| 音乐 | yīn **yuè** | yīn **lè** ✗ |
| 重新 | **chóng** xīn | **zhòng** xīn ✗ |
| 了解 | **liǎo** jiě | **le** jiě ✗ |
| 长大 | **zhǎng** dà | zhǎng dà ✓ |
| 快乐 | kuài lè | kuài lè ✓ |

**为什么**：参考实现有分词和词性标注，本插件没有。要修得引入分词库或
上下文读音表，会显著增加体积和复杂度。

**怎么绕**：多音字是硬伤，暂时只能靠人工替换文本。

### 2. 英文按字母念

```
hello  →  h-e-l-l-o（5 个音节）
OK     →  o-k（2 个音节）
```

读的是**字母名**，不是单词读音。因为音库只有 407 个普通话音节，
没有英文音素。

**为什么**：参考实现用 CMU 词典查整词读音（`hello` → `HH AH0 L OW1`），
再映射到最接近的音节。本插件没带那个词典（体积大）。

**怎么绕**：可以接受就接受；不能接受就在配置里把 `max_chars` 调小，
或者只在纯中文场景用。

### 3. Markdown 链接里的 URL 会被念出来

```
[链接](http://a.com)
→ 念成「链接 + h-t-t-p-a-点-c-o-m」共 10 个音节
```

Bot 如果输出 Markdown 链接，URL 部分会变成噪音。

**怎么绕**：让 Bot 少输出链接，或在提示词里要求「不要用 Markdown 链接格式」。

### 4. 音节数不等于字数

`max_chars=150` 限制的是**原文字数**，但每个英文字母会变成 1 个音节。
所以：

```
150 个中文字  → 约 150 音节 → 音频约 13 秒
150 个英文字母 → 150 音节 → 音频约 13 秒
46 字符的 URL  → 35 音节
```

极端情况下音频会比较长。如果群里经常有长英文，把 `max_chars` 调到 80 左右。

### 5. 不支持日文/韩文

参考实现支持 11 种语言（走 IPA 映射），本插件只做了中文。
日文假名、韩文谚文会被直接跳过，不发音。

### 6. 音色固定，换不了

音库是 Coopanion 用 `edge-tts` 的 `zh-CN-XiaoyiNeural` 声音录的。
想换成别的音色（男声、你自己的声音），需要用 `build.py` 的思路
重新构建整个音库——需要 ffmpeg + praat-parselmouth + edge-tts，
不是改配置能解决的。

### 7. 流式模式下可能有延迟

如果 Bot 开了流式输出，本插件会等 `STREAMING_FINISH` 才合成，
所以是「文字全部生成完 → 再转语音 → 再发」，比非流式略慢一点。
这是为了避免把回复切成一条条碎片语音。

### 8. 没在真实 AstrBot 环境验证

**这一条必须说明**：本插件的钩子逻辑是照着 AstrBot 源码写的
（`on_decorating_result` + `ResultContentType`），用伪造的模块做了 67 项测试，
但**没有在真实运行的 AstrBot 实例里跑过**。

如果你遇到钩子不触发、语音发不出等问题，请带上日志提 issue。
